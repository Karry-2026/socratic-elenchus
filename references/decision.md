# 可选工具：决策场景

> 只在用户的问题是一个**选择**（要不要 X、选 A 还是 B）时加载。它们是工具，不是主干；主干仍是 `SKILL.md` 的五步。

## 1. 现实条件扫描

先看用户的回答是否取决于外部事实：

| 类型 | 典型信号 | 处理 |
|---|---|---|
| 钱 | 收入、负债、存款 | 先问数，再谈意义 |
| 身体 / 精神 | 累、失眠、撑不住 | 先确认程度，必要时停止追问 |
| 时间 | 期限、年龄、窗口期 | 问清截止点，否则「慢慢想」是假的 |
| 他人 | 家人、伴侣、老板 | 分出哪些是他能定的 |

原则：**事实没落地，谈概念是空转**。但只问与当前命题直接相关的那一条，别做成问卷。

## 2. 替换测试

用户说「我要 X」时问：

> 「如果换成 Y，同样能满足那个东西，你还要吗？」

- 还要 → 他要的是 X 本身。
- 不要了 → 他要的是 X 背后的东西，接着问那个东西还能怎么得到。

例：「我要更大的平台」→「如果小平台给你同样的机会，你还走吗？」——答案往往把「平台」换成「能往上走的路」。

## 3. 复合原因排序

用户说「原因很复杂、不是单一原因」时，不要找根因：

1. 让他把条件摊开列出来。
2. 让他排序：哪条最重要。
3. 问必要条件：「哪一条缺了，别的补不上？」
4. 若他说「都重要」→「如果只能满足一条，你选哪条？」

排序不是简化，是把「复杂」变成「可操作」。

## 4. 摩擦档位

| 档 | 行为 | 何时 |
|---|---|---|
| L0 直讲 | 直接给论证 + 最强反驳 + 出处 | 用户说「直接告诉我」 |
| L1 先给直觉 | 先问直觉，再给暂定回答并标注不确定 | 赶时间、没耐心 |
| L2 引导（默认） | 一问一答走完五步 | 大多数情况 |
| L3 攻防 | 用户必须回应「最强反对意见」 | 练论证、面试或谈判准备 |

降档不必征求同意，但要说一句：「我降一档，先给你个抓手。」

## 5. 用户说「你偏了」

立刻停，一句话复述他的核心：「你要的是 X，对吧？」确认后再走。**不解释、不辩解。**
