# 测试场景

四个固定场景，用于模拟实跑。每个场景给定**用户的三句话**，模型按 `SKILL.md` 产出 A1–A3 三轮回复。
刻意不给模型看 `examples/`——测的是**主干说明书**能否单独支撑行为。

| # | 场景 | 测什么 |
|---|---|---|
| S1 | 概念争议 | 定义澄清、反例、不宣布判决 |
| S2 | 论证自检 | 取核心主张、拆「因为」、前提暴露 |
| S3 | 决策 | 现实条件先行、替换测试、收束合规 |
| S4 | 卡住 / aporia | 连续「我不知道」时，是否给梯子、是否把困惑变成可继续的问题 |
| S5 | 中途喊停 | 「直接告诉我」是否立即生效、用户说停是否优先于轮次下限 |

## S1 概念争议

- U1：我觉得好内容就是有人看的内容。
- U2：播放量高就是好。
- U3：有些讲得挺扎实的，播放量一般。

## S2 论证自检

- U1：帮我看这段话：远程办公会毁掉团队文化，因为大家不见面就没法建立信任。
- U2：因为不在一起，很多话没法说。
- U3：……可能就是感觉吧，说不太清。

## S3 决策

- U1：我在纠结要不要接一个兼职。
- U2：钱是一方面，主要是想攒点作品。
- U3：但时间不够，我不确定值不值。

## S4 卡住 / aporia

- U1：我觉得自由就是不受限制。
- U2：能做想做的事吧。
- U3：……我不知道，这两个我说不清。

## S5 中途喊停

- U1：我觉得远程办公会毁掉团队文化，因为不见面就没法建立信任。
- U2：不见面就没有人情味。
- U3：反正就是感觉不对，说不上来。
- U4：别问了，你直接告诉我吧。

## 执行方式

1. 新开一个会话，只加载 `socratic-elenchus` 的 `SKILL.md`（不读 `examples/`）。
2. 依次输入 U1、U2、U3，记录模型的三轮回复。
3. 按 `docs/rubric.md` 打分，每条评分附原文片段。
4. 结果写入 `test/RESULTS.md`。

## 说明

这是**脚本化模拟**，不是真实用户测试：用户的第二、三句话是预置的，不随模型的提问而变。
它的作用是检验「规则能否被独立执行」，不能替代真实多轮对话（真实对话中用户的回答会跟着提问走）。
